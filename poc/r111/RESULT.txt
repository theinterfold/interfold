## Findings

### (A) SOURCE - C2 commitment/cost structure is MINIMAL (no I3/I14-class lever exists). RAN (cheapest-first, source).

The C2 cone (`circuits/lib/src/core/dkg/share_computation.nr`, 328 lines; both
SecretKeyShareComputation + SmudgingNoiseShareComputation exec() share the 5-block shape)
has NO `fn payload` / NO SAFE-sponge *transcript* at all. C2 emits commitments + range
proofs + a parity check only; there is no Fiat-Shamir challenge absorption inside the C2
circuit (the C3 challenge sponge `compute_share_encryption_challenge` lives in C3, not C2).
So the I3/I14 redundancy class (a raw element pushed into a transcript that is ALREADY
bound by a commitment) is STRUCTURALLY ABSENT from C2: there is no transcript to de-dup.

The 5 cost blocks (both C2a and C2b, each an ~equal-cost core):
  1. verify_secret_commitment   : secret -> expected_secret_commitment (C1's C2-side input).
     The ONLY binding of the secret to C1's public commitment. Load-bearing (drop it and the
     secret is unbound to C1 = the C1->C2 link the INVARIANTS require). NOT redundant.
  2. verify_secret_consistency  : y[i][j][0] == secret[i] for all i,j. THE Shamir
     evaluation-at-0 binding (the share vector's constant term IS the secret). Load-bearing;
     no commitment alternative (a commitment cannot bind the COEFFICIENTS equal to the
     secret - only a proof of the relation can). NOT redundant.
  3. check_range_bounds         : y[i][j][k>=1] in [0,q_j) for all k>=1. ALREADY vetted by
     I16 (r34, REJECTED-as-framed, RAN-from-source): `pack` is blind radix concat with NO
     per-limb range assert and SAFE `absorb` is pure field addition with NO range assert
     => the OUTER check_range_bounds is the SOLE share range proof into [0,q_j). Dropping it
     aliases a share coeff >= q_j inside the packed carrier. Load-bearing, exactly the I9
     situation (r1). NOT redundant.
  4. verify_parity_check        : H[j] * y[i][j]^T == 0 for all i,j (Reed-Solomon
     codeword). Load-bearing (T+1-of-N recoverability); no cheaper primitive. NOT redundant.
  5. commit_to_party_shares     : commitments[party][mod] = commitment(share_poly). This is
     the C2 PUBLIC OUTBOUND - it IS consumed: node_fold.nr:110-121 binds c2a/c2b_public
     (the per-(party,mod) commitments) to C3's `expected_message_commitment` for every
     non-self slot, so every commitment is load-bearing across the C2->C3 boundary. NOT
     internally redundant (it is the very thing C3 asserts against).

Conclusion (A): EVERY C2 cost block is load-bearing; there is no redundant raw-push, no
redundant block, no commitment-SAFE double-bind. C2 is MINIMAL as written. The one C2 lever
that WAS real (I16, the outer range check) was already REJECTED-as-framed in r34 and
re-confirmed here by the same source (pack/SAFE have no range assert). NO new C2 box-1
lever. C2's box-2 child is unchanged: the secure-8192/SWALL (N=19/T=9) leaf compiles OOM on
>=16GiB (r45: C2a 15.1 GiB, C2b 14.9 GiB) - that is a PROVISIONING card (owner directive
2026-09-05: box-2 32 GiB prod-only), not a source lever.
