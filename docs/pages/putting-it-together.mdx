# Putting it all together

CRISP is the reference application for the OpenVM compute path. The application server coordinates
the round. The program server generates the proof. Ciphernodes perform key generation and threshold
decryption.

## Prepare the program

1. Implement the FHE processor and input policy.
2. Use the same program source in the native host and guest.
3. Build the OpenVM guest, worker, and proving artifacts.
4. Derive the executable and VM commitments with the worker's `prepare` command.
5. Validate the worker configuration with `check`.

See [Writing the Secure Process](/write-secure-program) and
[Compute Provider Setup](/compute-provider). The CRISP reference guest cannot prove a different
application's input policy without a rebuild.

## Deploy the verifier path

1. Deploy the checked Halo2 verifier artifact, or select an existing verifier with the expected
   runtime hash.
2. Deploy the receipt adapter with the prepared executable and VM commitments.
3. Deploy the BFV ciphertext verifier with that adapter and receipt identity.
4. Configure the E3 program with the same adapter and identity.
5. Register the E3 program and set the protocol's ciphertext-verifier route.

Deployment settings must be explicit. There is no default verifier address or application identity.
Drain active rounds before a live migration because each round retains its request-time verifier.

## Connect the services

Set `program.openvm` in the Interfold configuration and run `interfold program start`. Set the
application server's program-service URL and externally reachable callback URL. Restrict service
admission and callback destinations to the deployment's intended network.

For CRISP, these settings are `PROGRAM_SERVER_URL` and `INTERFOLD_SERVER_URL`.

## Run the round

The application requests an E3 with the current request structure and quoted fee. The committee
publishes its proof-backed public-key commitment and retrievable key bytes. Participants submit
encrypted inputs through the application.

After the input deadline, CRISP waits for the indexed inputs and confirmed availability. It sends
those inputs and the full E3 domain to the program server. The OpenVM worker proves the computation,
recursively aggregates it, creates the EVM proof, and verifies the proof before returning it.

The HTTP callback contains the ciphertext, SAFE commitment, and compute-proof envelope. CRISP
validates the proof, publishes the ciphertext to the availability layer, and submits the output
reference. The protocol and application both verify the compute proof.

The committee then performs threshold decryption. A verified plaintext publication completes the E3
and settles its fee ledger.

## Verify the scope

Use the real-proof test to check the receipt and its negative cases. Use the live service test to
check the request, callback, and automatic publication. Record any mocked randomness, DKG, ballot,
availability, or decryption dependencies separately. Do not describe a mocked dependency as
proof-backed.

See [Verifying the Compute Provider](/verifying-the-compute-provider) for build and deployment
evidence.
