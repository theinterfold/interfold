# Installation

This page is for developers who build E3 programs. It shows how to install the `interfold` CLI,
which other tools the default project template needs, and how to verify the installation. At the
end, you have a working `interfold` command and a computer that is ready for the
[Quick Start](/build/quick-start).

To run a ciphernode for the network, read [Operator requirements](/operate/requirements) instead.

## Supported platforms

Each release publishes prebuilt archives for two platforms.

| Operating system | Architecture          | CLI archive                      |
| ---------------- | --------------------- | -------------------------------- |
| Linux            | x86_64                | `interfold-linux-x86_64.tar.gz`  |
| macOS            | Apple silicon (arm64) | `interfold-macos-aarch64.tar.gz` |

The releases do not include archives for other platforms, for example Linux on arm64 or macOS on
Intel. On these platforms, [build the CLI from source](#install-the-cli).

Each release also publishes `interfold-test-only-skip-proof-aggregation-linux-x86_64.tar.gz`. This
CLI has the `test-only-skip-proof-aggregation` Cargo feature, so its nodes can skip recursive proof
aggregation. Use it only for tests and CI, for example the end-to-end tests of an E3 program. Do not
use it on a network. The install script and `interfold update` do not install it.

## Developer tools

`interfold init` needs Git and pnpm. The default project template also starts a local chain,
compiles Rust code, and runs a web client, so it needs more tools.

| Tool                                                          | Version            | The template uses it to                                                                     |
| ------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------- |
| [Git](https://git-scm.com/downloads)                          | Any recent version | Clone the template and make the project repository.                                         |
| [Node.js](https://nodejs.org/en/download)                     | 22                 | Run the client, the coordination server, and Hardhat. The repository CI uses Node.js 22.    |
| [pnpm](https://pnpm.io)                                       | 10.7.1             | Install packages and run scripts. The `packageManager` field in `package.json` pins 10.7.1. |
| [Rust](https://rust-lang.org/tools/install/) (with `rustup`)  | 1.91.1             | Build and run the program server. `rust-toolchain.toml` in the template pins this version.  |
| [Foundry](https://github.com/foundry-rs/foundry)              | Current release    | Run `anvil`, the local chain that `pnpm dev:all` starts on port 8545.                       |
| A browser wallet, for example [MetaMask](https://metamask.io) | Any                | Sign the transactions that the client sends to the local chain.                             |

Some tools are necessary only for specific tasks.

| Tool                                                 | When you need it                                                                                                                                                             |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`cargo-openvm`](https://docs.openvm.dev) v2.0.2     | Real proofs (`program.dev: false`). `interfold program compile` builds the guest with it. See [Compute provider](/build/e3-program/compute-provider#run-a-compute-provider). |
| The CUDA toolkit and an NVIDIA GPU                   | Optional. The CUDA build of the OpenVM worker proves on the GPU; without it, the CPU worker proves.                                                                          |
| [tmux](https://github.com/tmux/tmux/wiki/Installing) | `pnpm dev:all --tmux`, which opens each process in its own tmux pane.                                                                                                        |
| [Noir](https://noir-lang.org/docs) (`nargo`)         | Only to write your own circuits. The repository CI uses `v1.0.0-beta.26`. See [Noir circuits](/build/noir-circuits).                                                         |

For a released node, the setup commands install these components:

- **Barretenberg (`bb`) and the protocol circuits.** `interfold noir setup` downloads the versions
  pinned in the CLI. Source builds pin `bb` 5.2.0. The template scripts run this command for you.
- **The OpenVM guest toolchain.** `cargo-openvm` installs the toolchain it needs. The local scripts
  run in dev mode by default, so they do not use OpenVM.

Source builds need circuit artifacts that match the checkout and its `bb` 5.2.0 pin. Pull matching
artifacts with `pnpm store:circuits pull`, or rebuild them. Do not reuse an archive from an older
toolchain. See [the source toolchain instructions](/build/noir-circuits#toolchain).

<Callout type='info'>
  When you run `cargo` in a folder that has a `rust-toolchain.toml` file, `rustup` uses the Rust
  version in that file. With Corepack enabled (`corepack enable`), pnpm uses the version in the
  `packageManager` field.
</Callout>

## Install the CLI

Select an installation method. The install script is the recommended method.

<Tabs items={['Install script', 'Release archive', 'From source']}>
<Tabs.Tab unmount={false}>

<Steps>

### Run the install script

```bash
curl -fsSL https://raw.githubusercontent.com/theinterfold/interfold/main/install | bash
```

If `curl` is not available, use `wget`:

```bash
wget -qO- https://raw.githubusercontent.com/theinterfold/interfold/main/install | bash
```

The script detects your platform, downloads the `interfold` archive for the latest release, and
installs the binary to `~/.local/bin/interfold`. If `~/.local/bin` is not in your `PATH`, the script
prints the commands to add it for bash, zsh, and fish.

### Select a release (optional)

To install a specific release, give the `--version` option to the script, or set
`INTERFOLD_VERSION`:

```bash
# With the script option
curl -fsSL https://raw.githubusercontent.com/theinterfold/interfold/main/install | bash -s -- --version v0.19.0

# With the environment variable
curl -fsSL https://raw.githubusercontent.com/theinterfold/interfold/main/install | INTERFOLD_VERSION=v0.19.0 bash
```

A tag without the `v` prefix, for example `0.19.0`, also works. To install in another folder, add
`--dir <folder>` or set `INTERFOLD_INSTALL_DIR`. For a folder that your user cannot write to, run
the script with `sudo bash` instead of `bash`.

</Steps>

</Tabs.Tab>
<Tabs.Tab unmount={false}>

<Steps>

### Download the archive

Open the [releases page](https://github.com/theinterfold/interfold/releases). Download the
`interfold` archive for your platform from the **Assets** list, for example
`interfold-linux-x86_64.tar.gz`.

### Verify the checksum

Calculate the SHA-256 checksum of the archive:

```bash
# Linux
sha256sum interfold-linux-x86_64.tar.gz
# macOS
shasum -a 256 interfold-macos-aarch64.tar.gz
```

Compare the result with the **Checksums** section of the release notes. The two values must be
identical.

### Extract the binary

```bash
tar -xzf interfold-linux-x86_64.tar.gz
```

The archive contains one file, `interfold`.

### Install the binary

Move the binary to a folder in your `PATH`. The install script uses `~/.local/bin`.

```bash
mkdir -p ~/.local/bin
mv interfold ~/.local/bin/interfold
chmod 755 ~/.local/bin/interfold
```

</Steps>

</Tabs.Tab>
<Tabs.Tab unmount={false}>

A source build needs Rust 1.91.1 and the Solidity compiler `solc` in your `PATH`. The build script
of the `e3-evm` crate calls `solc`, and the build stops if `solc` is not available.

<Steps>

### Clone the repository

```bash
git clone https://github.com/theinterfold/interfold.git
cd interfold
```

To build a specific release, check out its tag, for example `git checkout v0.18.0`.

### Build and install the CLI

```bash
cargo install --locked --path ./crates/cli --bin interfold -f
```

Cargo installs the binary to `~/.cargo/bin/interfold`.

</Steps>

<Callout type='info'>
  The template integration test (`pnpm test:integration`) needs a CLI that is built with the
  `test-only-skip-proof-aggregation` Cargo feature. Of the release archives, only the [test-only
  archive](#supported-platforms) has this feature. To build it, add `--features
  test-only-skip-proof-aggregation` to the `cargo install` command.
</Callout>

</Tabs.Tab>
</Tabs>

## Change the installed version

`interfold update` replaces the binary that runs the command with another release. It downloads the
archive for your platform from the GitHub release. Use the command to upgrade and to downgrade.

| Command                              | Result                                                                                                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `interfold update`                   | Installs the latest release.                                                                                            |
| `interfold update --version v0.19.0` | Installs the release with that tag, newer or older than the installed release. A tag without the `v` prefix also works. |
| `interfold update --version dev`     | Installs the most recently published release, stable or pre-release (the `dev` channel).                                |
| `interfold uninstall`                | Removes the `interfold` binary. The configuration, the keys, and the node data stay.                                    |

`interfold upgrade` is another name for `interfold update`. When the installed version and the
target release are the same, the command prints `interfold is already at <tag>` and makes no change.

The command writes the new binary to a temporary file in the same folder, and then renames that file
to the name of the binary. A running node continues to use the old release until you restart it. If
your user cannot write to the folder of the binary, for example `/usr/local/bin`, run the command
with `sudo`.

<Callout type='warning'>
  Release 0.19.0 and earlier do not have the `update` command. To change the version of such a
  release, or to go back to a newer release after a downgrade to such a release, run the install
  script with `--version <TAG>`. If the binary is not in `~/.local/bin`, also give its folder with
  `--dir <folder>`.
</Callout>

The `interfoldup` installer of older releases is not necessary. To remove it, run
`rm ~/.local/bin/interfoldup`.

## Verify the installation

<Steps>

### Check the version

```bash
interfold --version
```

The command prints the CLI version, for example `interfold 0.18.0`.

### Check the build revision

```bash
interfold rev
```

The command prints the short Git commit hash that the binary was built from. Run it in a folder that
is not an Interfold project.

### Check the compiled features

```bash
interfold rev --features
```

The CLI from the `interfold-<platform>` archive prints nothing. A binary built with
`test-only-skip-proof-aggregation` prints that feature name. The CLI from the test-only archive is
such a binary.

</Steps>

<Callout type='info'>
  In a project folder with a running ciphernode, the CLI sends `interfold rev` to that node. The
  output is then the revision of the node, which can differ from the revision of your CLI.
</Callout>

## Troubleshooting

| Problem                                               | Cause and fix                                                                                                      |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `command not found: interfold`                        | The install folder is not in your `PATH`. Add `~/.local/bin` to your `PATH`.                                       |
| `unrecognized subcommand 'update'`                    | The installed CLI is release 0.19.0 or earlier. Run the install script.                                            |
| `No compatible binary found for platform: <platform>` | The install script found no `interfold` archive for your platform. Build the CLI from source.                      |
| `No release archive exists for <os> on <arch>`        | `interfold update` found no archive for your platform. Build the CLI from source.                                  |
| `GitHub API request for release <tag> failed`         | The tag does not exist, or GitHub is not available. Check the tag on the releases page.                            |
| `Permission denied for <folder>`                      | `interfold update` or `interfold uninstall` cannot write to the folder of the binary. Run the command with `sudo`. |
| The source build stops with `solc must be installed`  | Install the Solidity compiler `solc` and run the build again.                                                      |
