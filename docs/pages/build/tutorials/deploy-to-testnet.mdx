# Deploy to Sepolia

<Badge tone='testnet'>Testnet</Badge>

This tutorial moves an E3 program from the local stack to the Sepolia testnet. It is for developers
who have a working program from the default template. On Sepolia, you use the Interfold contracts
that the Interfold team deployed and the ciphernodes that operators run. You deploy only your
program contract. At the end, your program is on Sepolia, the owner of the Interfold contract can
register it, and your server and client use the testnet.

<Callout type='warning'>
  Do not submit real private data on Sepolia. The `insecure-512` preset is not secure, and the
  manifest marks the Sepolia deployment with `mocks: true`, which means that it records mock
  verifier contracts.
</Callout>

<Callout type='warning'>
  On 25 September 2026, the Sepolia protocol contracts predate the node release gate.
  `nodeReleaseRegistry()` on the Sepolia `Interfold` contract reverts. A 0.18.0 ciphernode reads
  this value at startup, so it stops with `failed to read Interfold release dependencies`.
  Ciphernodes on this release cannot serve Sepolia E3s until the Sepolia deployment is upgraded.
</Callout>

## What changes on Sepolia

Locally, `pnpm dev:all` deploys its own Interfold contracts, and the deployer owns them. On Sepolia,
the Interfold team owns the protocol contracts. This changes four steps of the local flow.

| Step                         | Local (`pnpm dev:all`)                                             | Sepolia                                                                                          |
| ---------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Program registration         | `deployTemplate` calls `registerE3Program`.                        | `registerE3Program` is `onlyOwner`. The owner of the Interfold contract must call it.            |
| Protocol ciphertext verifier | `deployTemplate` calls `setCiphertextVerifier` with your image ID. | `setCiphertextVerifier` is `onlyOwner`. One verifier serves every BFV program on the deployment. |
| Data availability            | The coordination server stores the output (`mode: mock_http`).     | Ciphernodes read the output from Avail (`mode: avail`).                                          |
| Ciphernodes                  | Five local nodes from `scripts/dev_ciphernodes.sh`.                | The nodes of registered operators. Sortition needs enough of them for the committee size.        |

The first two rows mean that you cannot run `deployTemplate` on Sepolia unchanged. The owner-only
calls revert for any other signer. The last two rows decide if an E3 of your program can complete.
The procedure below covers each row.

## Before you start

- A project from the default template. See
  [Build a Complete E3 Program](/build/tutorials/write-e3-program).
- A deployer account with Sepolia ETH. Use any public Sepolia faucet.
- A Sepolia RPC endpoint. Hardhat uses HTTPS. The server and the client can use HTTPS or WebSocket.
- Foundry (`cast`) for the checks.

<Steps>

### Set the Sepolia variables

The Hardhat configuration of the template reads `RPC_URL`, `PRIVATE_KEY`, and `MNEMONIC` from `.env`
through `dotenv`. Create `.env` in the project root. The template `.gitignore` excludes it.

```bash filename=".env"
RPC_URL=https://<your Sepolia HTTPS RPC>
PRIVATE_KEY=0x<deployer private key>
```

Set the same values in your shell for the `cast` commands, and add the Interfold address:

```bash
source .env
INTERFOLD_ADDRESS=0x3E856E24c7a95d0e04d387f847DA6FA9f6F6c20C
```

### Get test tokens

E3 fees are paid in the fee token (`MockUSDC`). Call `faucet()` on the Faucet contract:

```bash
cast send 0x6e281411C055BEEbD74bDFcB9aB095aa98907F85 "faucet()" --rpc-url $RPC_URL --private-key $PRIVATE_KEY
```

The faucet sends 200 FOLD and 200 fee tokens (`contracts/test/Faucet.sol`). It sends each token only
if your balance of that token is below 200. It reverts with `You have enough tokens` if you need
neither. An operator with a configured node can run `interfold faucet` instead.

### Record the Interfold address for the deploy script

The template deploy helpers read addresses from `deployed_contracts.json`, one object for each
Hardhat network name (`readDeploymentArgs`). Add a `sepolia` object next to `localhost`:

```json filename="deployed_contracts.json"
{
  "localhost": { "...": "..." },
  "sepolia": {
    "Interfold": {
      "address": "0x3E856E24c7a95d0e04d387f847DA6FA9f6F6c20C",
      "blockNumber": 11534993
    }
  }
}
```

### Add the Sepolia chain to interfold.config.yaml

`interfold print-env` reads addresses from `interfold.config.yaml`. Add a `sepolia` entry to
`chains`. The deploy script adds `e3_program` to it.

```yaml filename="interfold.config.yaml"
chains:
  # - name: 'localhost' ... (keep the local entry)
  - name: 'sepolia'
    rpc_url: 'wss://<your Sepolia WebSocket RPC>'
    chain_id: 11155111
    contracts:
      interfold:
        address: '0x3E856E24c7a95d0e04d387f847DA6FA9f6F6c20C'
        deploy_block: 11534993
      ciphernode_registry:
        address: '0x374F4542eC634d5437Dd65020781A9D9Df9c2AB8'
        deploy_block: 11534965
      bonding_registry:
        address: '0x90250Dc48CBe109fFaA02AeAFbFBdbF12D7BD4d4'
        deploy_block: 11534966
      fee_token:
        address: '0xC35B783cA97710be47Fc81D10dADc895EfcD865c'
        deploy_block: 11534960
```

### Write a Sepolia deploy script

Create `scripts/deploy-sepolia.ts`. It is `deploy/default.ts` without the two owner-only calls. Like
the CRISP deploy script, it deploys `PoseidonT3` when the network has no record for it.

```ts filename="scripts/deploy-sepolia.ts"
import {
  getDeploymentChain,
  readDeploymentArgs,
  storeDeploymentArgs,
  updateE3Config,
} from '@interfold/contracts/scripts'
import hre from 'hardhat'

async function main() {
  const { MyProgram__factory: MyProgramFactory } = await import('../types/factories/contracts')
  const { ensureTemplateCwd, INTERFOLD_CONFIG_FILE } = await import('./template-paths')
  ensureTemplateCwd()
  const { ethers } = await hre.network.connect()
  const [owner] = await ethers.getSigners()
  const chain = getDeploymentChain(hre)

  const interfoldAddress = readDeploymentArgs('Interfold', chain)?.address
  if (!interfoldAddress)
    throw new Error(`No Interfold record for ${chain} in deployed_contracts.json`)

  let poseidonT3Address = readDeploymentArgs('PoseidonT3', chain)?.address
  if (!poseidonT3Address || (await ethers.provider.getCode(poseidonT3Address)) === '0x') {
    const poseidonT3 = await ethers.deployContract('PoseidonT3')
    await poseidonT3.waitForDeployment()
    poseidonT3Address = await poseidonT3.getAddress()
    storeDeploymentArgs(
      { address: poseidonT3Address, blockNumber: await ethers.provider.getBlockNumber() },
      'PoseidonT3',
      chain,
    )
  }

  // MockRISC0Verifier accepts every seal. Use a real RISC Zero verifier for real proofs.
  const verifier = await ethers.deployContract('MockRISC0Verifier')
  await verifier.waitForDeployment()
  const imageId = await ethers.deployContract('ImageID')
  await imageId.waitForDeployment()
  const programId = await imageId.PROGRAM_ID()

  const factory = await ethers.getContractFactory(
    MyProgramFactory.abi,
    MyProgramFactory.linkBytecode({
      'npm/poseidon-solidity@0.0.5/PoseidonT3.sol:PoseidonT3': poseidonT3Address,
    }),
    owner,
  )
  const program = await factory.deploy(interfoldAddress, await verifier.getAddress(), programId)
  await program.waitForDeployment()
  const programAddress = await program.getAddress()

  storeDeploymentArgs(
    { address: programAddress, blockNumber: await ethers.provider.getBlockNumber() },
    'MyProgram',
    chain,
  )
  updateE3Config(chain, INTERFOLD_CONFIG_FILE, { MyProgram: 'e3_program' })
  console.log(`MyProgram deployed at ${programAddress}`)
}

main().catch((error) => {
  console.error(error)
  process.exit(1)
})
```

If your `MyProgram` constructor has more arguments (for example an input verifier), deploy them
first and add them to `factory.deploy`.

### Deploy the program

Compile, then run the script on the `sepolia` network of `hardhat.config.ts`:

```bash
pnpm compile
pnpm exec hardhat run scripts/deploy-sepolia.ts --network sepolia
```

The script prints `MyProgram deployed at 0x...`. It records the address in `deployed_contracts.json`
and adds `e3_program` to the `sepolia` entry of `interfold.config.yaml`.

### Get the program registered

Check the registration and the owner of the Interfold contract:

```bash
cast call $INTERFOLD_ADDRESS "e3Programs(address)(bool)" <MyProgram address> --rpc-url $RPC_URL
cast call $INTERFOLD_ADDRESS "owner()(address)" --rpc-url $RPC_URL
```

The first call returns `false` until the owner calls `registerE3Program`. Send the program address
to the Interfold team and ask for registration. The task `interfold:enableE3` in
`packages/interfold-contracts` (`pnpm e3:enable --e3-address <address> --network sepolia`) makes the
call when its signer is the owner. For any other signer, it stops with
`Submit registerE3Program through the owner Safe.`

At registration, the Interfold contract checks with ERC-165 that the program supports `IE3Program`
and `IE3ProgramDataAvailability`. The template does. A request for an unregistered program reverts
with `E3ProgramNotAllowed`.

### Check the protocol ciphertext verifier

Every output proof must pass the ciphertext verifier that the owner set for BFV. Read it:

```bash
cast call $INTERFOLD_ADDRESS "getCiphertextVerifier(bytes32)(address)" $(cast keccak "fhe.rs:BFV") --rpc-url $RPC_URL
```

If the address is a `Risc0BfvCiphertextVerifier`, read its image ID and its RISC Zero verifier:

```bash
cast call <verifier address> "imageId()(bytes32)" --rpc-url $RPC_URL
cast call <verifier address> "risc0Verifier()(address)" --rpc-url $RPC_URL
```

Your output proofs must pass that RISC Zero verifier for that image ID. The program server in dev
mode (`program.dev: true`) makes mock proofs, which only a mock RISC Zero verifier accepts. The
Interfold contract copies the current verifier into each E3 at request time, so a later change
applies only to new requests. See
[Verify the Compute Provider](/build/e3-program/verify-compute-provider).

### Replace the local data-availability check

Sepolia ciphernodes read the output ciphertext from Avail (`data_availability.mode: avail` in the
Sepolia configurations). They use the block and leaf index that `verifyDataAvailability` returns.
The template version returns zero for both, so a Sepolia committee cannot read your output.

Delegate the check to `AvailVectorXDataAvailabilityVerifier` from `@interfold/contracts`, as
`CRISPProgram` does:

```solidity filename="contracts/MyProgram.sol"
IDataAvailabilityVerifier public immutable dataAvailabilityVerifier;

function verifyDataAvailability(
  bytes32 expectedContentHash,
  bytes calldata proof
) external view override returns (IDataAvailabilityVerifier.DataReference memory receipt) {
  receipt = dataAvailabilityVerifier.verifyDataAvailability(expectedContentHash, proof);
  if (receipt.contentHash != expectedContentHash) revert DataAvailabilityHashMismatch(expectedContentHash, receipt.contentHash);
}
```

Set `dataAvailabilityVerifier` in the constructor. Deploy the verifier with the Sepolia bridge and
VectorX addresses from `AVAIL_VECTORX.sepolia` in `@interfold/contracts/scripts`. Add
`@interfold/contracts/contracts/verifiers/AvailVectorXDataAvailabilityVerifier.sol` to
`npmFilesToBuild` in `hardhat.config.ts` so that Hardhat compiles it.

The coordination server must then publish the output bytes to Avail and pass the VectorX proof as
`availabilityProof` to `publishCiphertextOutput`. The template server does not do this. The CRISP
server in `examples/CRISP/server` does, and
[`agent/flow-trace/08_DATA_AVAILABILITY.md`](https://github.com/theinterfold/interfold/blob/main/agent/flow-trace/08_DATA_AVAILABILITY.md)
describes the flow.

### Point the server at Sepolia

In `server/index.ts`, change the chain of the SDK from `hardhat` to `sepolia`:

```ts filename="server/index.ts"
import { sepolia } from 'viem/chains'

// in createPrivateSDK()
sdkInstance = InterfoldSDK.create({
  rpcUrl: RPC_URL,
  privateKey: PRIVATE_KEY as `0x${string}`,
  contracts: {
    interfold: INTERFOLD_CONTRACT as `0x${string}`,
    ciphernodeRegistry: CIPHERNODE_REGISTRY_CONTRACT as `0x${string}`,
    feeToken: FEE_TOKEN_CONTRACT as `0x${string}`,
  },
  chain: sepolia,
  thresholdBfvParamsPresetName: 'INSECURE_THRESHOLD_512',
})
```

`runProgram` reads the `InputPublished` events from block 0. Some RPC providers limit the block
range of a log query. If yours does, set `fromBlock` to the deploy block of your program.

Start the program server and the coordination server. `interfold print-env` prints `RPC_URL`,
`INTERFOLD_ADDRESS`, `REGISTRY_ADDRESS`, `BONDING_REGISTRY_ADDRESS`, `E3_PROGRAM_ADDRESS`, and
`FEE_TOKEN_ADDRESS` for the chain:

```bash
interfold program start
```

```bash
export $(interfold print-env --chain sepolia)
export PRIVATE_KEY=0x<server key> CHAIN_ID=11155111
pnpm tsx ./server/index.ts
```

The server account pays gas for `publishCiphertextOutput`, so it needs Sepolia ETH.

### Point the client at Sepolia

The client already includes the `sepolia` chain in its wagmi configuration. Start it with the
Sepolia addresses:

```bash
cd client
export $(interfold print-env --vite --chain sepolia)
pnpm dev
```

The client requests E3s with `paramSet: 0`, and the SDK uses `INSECURE_THRESHOLD_512` by default
(`VITE_THRESHOLD_BFV_PARAMS_PRESET_NAME`). Keep the two values in agreement. Sepolia accepts the
param sets 0 (`insecure-512`) and 1 (`secure-8192`). The mainnet contracts accept only 1.

### Request an E3

Open `http://localhost:3000`, connect a wallet on Sepolia with fee tokens, and request an E3. Each
stage waits for Sepolia blocks, so an E3 takes longer than on the local chain, where `anvil` makes
one block each second. To follow the E3 from a script, listen to the same events as the template:

```ts
await sdk.onInterfoldEvent(InterfoldEventType.E3_REQUESTED, (event) =>
  console.log('requested', event.data.e3Id),
)
await sdk.onInterfoldEvent(RegistryEventType.COMMITTEE_PUBLIC_KEY_CHUNK_PUBLISHED, (event) =>
  console.log('key chunk', event.data.e3Id),
)
await sdk.onInterfoldEvent(InterfoldEventType.CIPHERTEXT_OUTPUT_REFERENCE_PUBLISHED, (event) =>
  console.log('output', event.data.e3Id),
)
await sdk.onInterfoldEvent(InterfoldEventType.PLAINTEXT_OUTPUT_PUBLISHED, (event) =>
  console.log('result', event.data.plaintextOutput),
)
```

## Deploy scripts and tasks

| Location                       | Command                                                                                | What it does                                                                                                                   |
| ------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Template                       | `pnpm dev:all`                                                                         | Runs `scripts/deploy-local.ts` on `localhost`: `deployInterfold(true, false)`, then `deployTemplate()`.                        |
| Template                       | `pnpm hardhat ciphernode:admin-add --ciphernode-address <address> --network localhost` | Adds a ciphernode with admin privileges. It needs account impersonation (Anvil or Hardhat), so it works only on a local chain. |
| `packages/interfold-contracts` | `pnpm e3:enable --e3-address <address> --network <name>`                               | Registers an E3 program. The signer must be the owner of the Interfold contract.                                               |
| `packages/interfold-contracts` | `pnpm run deploy --network <name>`                                                     | Deploys the protocol contracts (`scripts/run.ts`, `deployInterfold`). This is for the protocol owner.                          |
| `packages/crisp-contracts`     | `pnpm deploy:contracts --network sepolia`                                              | Deploys CRISP and its verifiers, and wires them only when the signer owns the Interfold contract.                              |

`deployInterfold` accepts mock contracts on chain ID 11155111. On other chains it refuses mocks
unless `ALLOW_MOCKS_ON_PRODUCTION=true` is set.

## Troubleshooting

| Error or symptom                             | Cause                                                                   | Fix                                                                                   |
| -------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `OwnableUnauthorizedAccount` from the deploy | The script calls `registerE3Program` or `setCiphertextVerifier`.        | Use `scripts/deploy-sepolia.ts`, which leaves out the owner-only calls.               |
| `E3ProgramNotAllowed` on request             | The program is not registered.                                          | Ask the owner of the Interfold contract to call `registerE3Program`.                  |
| `ERC20InsufficientAllowance` on request      | The fee token allowance is lower than the fee.                          | Call `approveFeeToken(fee)` with the fee from `getE3Quote`, and wait for the receipt. |
| `FeeExceedsMaximum` on request               | The fee changed after the quote.                                        | Get a new quote and request again.                                                    |
| `InvalidInputDeadlineStart` on request       | `inputWindow[0]` is earlier than the block time.                        | Compute the window with `calculateInputWindow(publicClient, duration)`.               |
| No committee key                             | Sortition did not select a full committee, or the DKG did not finish.   | Read the stage with `getE3Stage`. If it is `Failed`, request a new E3.                |
| `InvalidOutput` on output publication        | The protocol verifier or `MyProgram.verify` rejected the compute proof. | Check the protocol ciphertext verifier and your image ID (see the steps above).       |
| The E3 does not finish after the output      | The committee cannot read the output from Avail.                        | Replace the local data-availability check, and publish the output to Avail.           |
