# System Requirements

This page covers the hardware, software, and network requirements for running the various components
of the Interfold protocol: ciphernodes, compute providers, and development environments.

## Ciphernode Requirements

A ciphernode participates in threshold cryptography (DKG, decryption) and generates zero-knowledge
proofs. The workload is CPU and memory intensive, especially during DKG and proof generation.

### Minimum (Development / Testnet)

| Component   | Specification                            |
| ----------- | ---------------------------------------- |
| **CPU**     | 4+ modern cores (x86-64)                 |
| **RAM**     | 16 GB                                    |
| **Disk**    | 100 GB SSD                               |
| **Network** | Stable broadband, UDP port open for QUIC |

### Recommended (Production / Mainnet)

| Component   | Specification                         |
| ----------- | ------------------------------------- |
| **CPU**     | 8+ modern cores (x86-64, AVX2)        |
| **RAM**     | 32 GB DDR5 (or DDR4 ECC)              |
| **Disk**    | 500 GB NVMe SSD                       |
| **Network** | Low-latency broadband, unfiltered UDP |

### Operating System

| Platform | Status                       |
| -------- | ---------------------------- |
| Linux    | ✅ Fully supported (x86_64)  |
| macOS    | ✅ Supported (Apple Silicon) |
| Windows  | ⚠️ Via WSL2 or Docker        |

> **Note:** The Linux binary is the primary target. macOS Apple Silicon binaries are available.
> Windows users should use WSL2 or the Docker image.

### Software Dependencies

| Dependency        | Minimum Version | Purpose                                |
| ----------------- | --------------- | -------------------------------------- |
| **Interfold CLI** | Latest release  | Node management and CLI operations     |
| **Rust**          | 1.91.1+         | Building from source                   |
| **WebSocket RPC** | —               | Real-time event listening (wss:// URL) |

### Network Requirements

- **QUIC port**: UDP must be unfiltered. Default QUIC port is set in your config
  (`interfold.config.yaml`). Cloud firewalls (AWS Security Groups, GCP firewall rules) must allow
  UDP inbound on this port.
- **WebSocket RPC**: The node subscribes to on-chain events via WebSocket. An HTTP-only RPC endpoint
  will fall back to polling and may miss events. Always use a `wss://` URL.
- **NAT**: If behind NAT, configure port forwarding for the QUIC UDP port.

### Disk Usage

| Data                      | Sizing behavior                                                          |
| ------------------------- | ------------------------------------------------------------------------ |
| Event log and proof blobs | Grows with retained E3 history; completed E3 records are not auto-pruned |
| Circuit artifacts         | Several gigabytes per built preset and committee combination             |
| Logs                      | Depends on log level and rotation policy                                 |

Large local events are stored in content-addressed `event-blobs-v1` files beside the event log.
Referenced blobs remain part of durable history after an E3 completes. Startup removes only files
that were synced but never referenced by a committed log record.

Use the 100 GB testnet and 500 GB production values above as initial allocations, not retention
estimates. Monitor free space and growth per E3, configure log rotation, and expand the volume
before it reaches capacity. Back up the event log and blob directory together. Use SSD storage
because slow I/O can cause missed protocol windows.

## Compute Provider Requirements

The OpenVM worker needs resources separate from the ciphernode baseline. The native HTTP service
starts the worker as a separate process. It does not send work to a proving market.

CUDA proving requires a compatible NVIDIA GPU, driver, CUDA toolkit, and a worker built for that GPU
architecture. Set `segment_memory_bytes` below the memory available to the worker. Provision host
RAM and SSD space for the application and aggregation keys, Halo2 key, KZG parameters, and temporary
proof files. Measure the largest supported round on the actual deployment hardware before setting
the compute deadline. There is no validated universal minimum for every round size.

See [Compute Provider](/compute-provider) and `crates/support/openvm/README.md` for the pinned
toolchain and artifact preparation. CPU workers are supported, but GPU timing does not establish
their capacity.

## Resource Scaling Guide

| Workload         | Committee `(N,T,H)` | Relative load | Notes                                    |
| ---------------- | ------------------- | ------------- | ---------------------------------------- |
| Idle ciphernode  | —                   | Low           | Event sync, P2P, and health checks       |
| Minimum DKG      | `(3,1,2)`           | Lowest        | Default local and integration-test shape |
| Micro DKG        | `(9,4,5)`           | Intermediate  | More C3 fan-out and recursive proof work |
| Small DKG        | `(19,9,14)`         | Highest       | Largest supported committee shape        |
| Compute provider | Program-specific    | Variable      | Depends on FHE and proving backend       |

Committee size and BFV preset are separate build choices. `secure-8192` uses much larger polynomials
than `insecure-512`, and C3 fan-out grows quadratically with N. Do not infer production sizing from
a Minimum insecure test. Benchmark the exact preset, committee, proof concurrency, and hardware with
`circuits/benchmarks/run_benchmarks.sh` before deployment.

> **Memory tip:** If your node starts OOM-killing during DKG, this is a resource constraint, not a
> software bug. Add more RAM or reduce parallelism settings.

## Monitoring Resource Usage

Use the [embedded dashboard](/tutorials/using-the-dashboard) to monitor node health. For
system-level monitoring:

```bash
# Check memory usage
free -h

# Monitor CPU and memory per process
htop

# Check disk usage
df -h

# Monitor network connections (QUIC uses UDP)
ss -ulnp | grep <quic_port>
```
