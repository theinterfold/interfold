# Writing the Secure Process

The Secure Process computes over encrypted inputs and derives the proof statement. The native host
and OpenVM guest use the same `fhe_processor` and `policy` functions.

`ComputeInput` contains BFV parameters, indexed ciphertext bytes, and the corresponding
`PublishedData` entries. Each entry carries the published commitment and program-specific metadata.
The input policy reconstructs the input leaves and selects the inputs that contribute to the result.

The guest must derive the input root from those inputs. An independently supplied leaf list could
match the contract while the computation uses different ciphertexts.

The application must compare the proof's input root with its own on-chain root.
`OpenVmBfvCiphertextVerifier` verifies the proof envelope but does not know the application's
input-tree policy.

## Processor

A BFV addition processor uses the decoded parameters supplied by `FHEProcessorInput`:

```rust
use e3_compute_provider::FHEProcessorInput;
use fhe::bfv::Ciphertext;
use fhe_traits::{DeserializeParametrized, Serialize};

pub fn fhe_processor(input: &FHEProcessorInput<'_>) -> Vec<u8> {
    let mut sum = Ciphertext::zero(input.params);
    for (bytes, _) in input.ciphertexts {
        let ciphertext = Ciphertext::from_bytes(bytes, input.params).unwrap();
        sum += &ciphertext;
    }
    sum.to_bytes()
}
```

The processor must use the selected inputs, not a second input collection. The program's `policy()`
function returns the matching `InputPolicy`.

CRISP's policy binds the ciphertext hash, SAFE commitment, slot, and parent index into each leaf. It
selects the current valid chain head for each slot. It does not simply count every submitted
ciphertext. See `examples/CRISP/program/src/lib.rs` for the canonical implementation.

## Guest and host

The reference OpenVM guest uses:

```rust
let (result, _) = input.input.run(
    e3_user_program::fhe_processor,
    e3_user_program::policy(),
).expect("Ciphertext aggregation failed");
```

The guest builds a `ComputeJournal` from the request domain and derived result. It reveals SHA-256
of the nine ABI words. The worker verifies that the proved digest matches the native host's expected
journal before returning a seal.

`crates/support/host/src/lib.rs` is the native implementation.
`crates/support/openvm/guest/src/main.rs` is the guest entry point. The reference support workspace
builds CRISP's program. A custom application must build both paths against its own program source
and deploy the resulting identity.

## Tests

Test the processor and policy independently before proving. Include reordered inputs, missing
metadata, invalid commitments, parent-chain changes, and parameter mismatches. Compare native and
guest results for the same fixture.

A real proof test must verify the receipt and reject changed journal fields, application identities,
and proof data. A live service test must also exercise HTTP dispatch, callback delivery, and
automatic ciphertext publication. Neither test implies that unrelated dependencies were real.
