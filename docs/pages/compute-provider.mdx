# Compute provider setup

The program server runs an E3 program's Secure Process and proves its execution with OpenVM. The
CRISP server sends the indexed encrypted inputs to this service when the input window closes. The
service returns the aggregate ciphertext, its SAFE commitment, and the compute proof by HTTP
callback. CRISP publishes the output after data-availability verification.

The current backend is OpenVM. The worker proves locally on the configured machine. No
proving-market wallet or program upload is required.

## Build the worker and guest

Use the Rust version in `rust-toolchain.toml` and the OpenVM CLI and guest toolchain for the
repository's pinned SDK version. CUDA workers also need compatible GPU drivers and runtime
libraries.

From the repository root:

```sh
pnpm openvm setup-fhe
pnpm openvm guest build
pnpm openvm guest keygen --app-only
pnpm openvm prover-build --features cuda
pnpm openvm service-build --release
```

The detailed artifact preparation and worker configuration are in
[`crates/support/openvm/README.md`](https://github.com/theinterfold/interfold/blob/main/crates/support/openvm/README.md).
Keep deployment paths, proving keys, inputs, and proofs outside committed source.

The reference guest implements CRISP's policy. A different program must use matching host and guest
builds for its own `fhe_processor` and `policy`.

## Start the program server

Set deployment-local absolute paths:

```yaml
program:
  dev: false
  openvm:
    repository: ${OPENVM_REPOSITORY}
    prover_bin: ${OPENVM_PROVER_BIN}
    prover_config: ${OPENVM_PROVER_CONFIG}
```

```sh
interfold program compile
interfold program start
```

The service validates the configured executable, keys, application commitments, and verifier
artifact before it accepts work. Missing configuration fails startup. `program.dev: true` explicitly
selects an unproved test runner. It cannot pass a real OpenVM verifier.

Configure CRISP's `PROGRAM_SERVER_URL` to reach the program server. Configure `INTERFOLD_SERVER_URL`
so the program server can reach CRISP's callback endpoint. The service defaults to loopback
port 13151. CRISP defaults to port 4000. Set `OPENVM_BIND_ADDR` and `CRISP_BIND_ADDR` when separate
listeners are needed.

Jobs are in memory, with one active computation per service process by default. Protect admission
and callback access. Reconcile interrupted jobs after a restart. The service does not provide a
durable job queue.

## On-chain verification

Deploy the checked OpenVM Halo2 verifier and its `OpenVmReceiptVerifier` adapter. Configure the
executable and VM commitments from the prepared application identity. Use that receipt adapter and
identity in both `OpenVmBfvCiphertextVerifier` and the E3 program.

CRISP's deployment requires `OPENVM_APP_EXE_COMMIT` and `OPENVM_APP_VM_COMMIT`. Supply either
`OPENVM_VERIFIER_ARTIFACT` with `OPENVM_VERIFIER_SHA256`, or `OPENVM_HALO2_VERIFIER` with
`OPENVM_HALO2_RUNTIME_CODE_HASH`. There are no default deployment values or mock compute-verifier
fallback.

The protocol verifies the domain and output. The application also verifies its stored parameter hash
and input root. Both checks are mandatory. See
[Verifying the Compute Provider](/verifying-the-compute-provider) for the source-to-deployment
checks.
