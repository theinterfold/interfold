v0.20.0 is a governance cutover from v0.19. Requests stay paused until governance has upgraded the
contracts and enough operators run this release.

- Run v0.20.0 only after the cutover batch has executed. The release requires protocol version 10
  and node generation 2, which a v0.19 node does not meet. v0.20.0 nodes connect only to nodes with
  the same protocol version.
- The storage schema changes from 8 to 9. Stop each node when it serves no active E3, back up its
  data, and reset its state with the new binary before the first start
  ([Reset node state](https://docs.theinterfold.com/operate/upgrades#reset-node-state)). The reset
  keeps the operator key and the libp2p key.
- DAppNode operators update the package when the node serves no active E3. The new package resets
  the state by itself before the node starts. Do not delete the package volume. DAppNode package
  publication is separate from this binary release.
- The release uses the `bb` 6.0.0 proving toolchain. Its proofs and verification keys do not verify
  against `bb` 5.2.0 nodes or verifiers.
- Governance can now require an identity credential for each bond owner. The check starts off. When
  the hosted dashboard shows the **Bond-owner identity** panel, verify the bond owner with the
  ZKPassport app ([Bond-Owner Identity](https://docs.theinterfold.com/operate/identity)). After
  governance makes the check required, an operator of an unverified bond owner stays active, but it
  gets no seat in a new committee.
- The first start acknowledges the release on chain and refreshes the operator.
